# Browser Back, Forward and direct lesson links

Status: implemented in the local web learner

Owner: SmartLingo web learner team

## Outcome

In Listening & videos, use **Next sentence** or **Skip** to advance from sentence 1 to sentence 2. Browser Back returns to sentence 1 with its answer, feedback and transcript visibility as they were in that visit. Browser Forward returns to sentence 2. Opening a lesson or section link in a new tab or after a refresh opens the same destination. This applies to French and Japanese, including downloaded lessons on the same browser origin.

Browser Back and Forward change the screen. Saved practice and progress are append-only. A visit to an older screen shows the appropriate saved or temporary state and writes zero learning events. Corrections to notebook entries continue through their edit controls.

## Route contract

The local web app uses `fr` and `ja` as URL language codes mapped to `fr-FR` and `ja-JP`. Angle brackets denote placeholders. URLs select the displayed language for that visit. The explicit language chooser sets the home preference. A valid direct link and a restored route can resolve while preference storage is unavailable.

| Destination | Path or pattern | Restore behavior |
| --- | --- | --- |
| Entry, Today and language chooser | `/`, `/today/fr`, `/today/ja`, `/languages` | `/` uses the existing home preference or opens the chooser. Normalize after initialization without adding a Back step. |
| Learn and topics | `/learn/<lang>`, `/learn/<lang>/topics/<topic-key>` | Restore tab, selected topic, list filters and scroll in the same tab. Use the encoded topic name or a compact key for a long name. An ambiguous or renamed topic offers the topic browser. |
| Shared lessons | `/lesson/fr/fr.essentials.repair/dialogue` and `/lesson/<lang>/<lesson-id>[/<stage>]` | Base link opens the current lesson and resolves saved resume. A valid explicit stage opens vocabulary, dialogue, meaning/picture matching, sentence building or the available finish view. It gives access to the relevant content and respects existing prerequisites for saving completion. |
| Daily courses | `/course/<lang>/<course-id>[/<day-id>[/<section-key>]]` | Base link resolves the current/resumable day. Explicit links identify a stable day and section. French links use the existing anchors under Dialogue, Practice and Try it. Japanese uses the existing authored block IDs. |
| Listening | `/learn/<lang>/listening[/<lesson-id>[/<question-key>]]` and `/learn/<lang>/listening/library` | Landing opens the player. Lesson and question select an authored sentence. Use `?topic=<topic-key>` for a topic-filtered deck. The library is its own destination. |
| Guided speaking | `/learn/<lang>/speaking[/<lesson-id>[/<revision>/<line-number>]]` | Restore lesson, dialogue turn and supported role selection for the visit. Existing dialogue lines have no separate IDs. Resolve the 1-based line within its lesson revision and fall back to a safe turn if the revision or order changes. |
| Japanese letters | `/learn/ja/letters[/<row-id>[/<mode>[/<character-id>]]]` | Resolve the stable kana row, study/recognition mode and optional character. Keep round order and feedback scoped to the recognized visit. |
| Review, Report and Profile | `/review/<lang>[/notebook\|practice]`, `/report/<lang>`, `/profile/<lang>` | Open populated feature views. Keep drafts and the current review queue in the tab; revisit a saved rating as already rated or return to the current queue. Profile groups remain disclosures unless a group needs an explicit link, such as support for offline setup. |
| Local editor | `/editor[/<lesson-id>[/<revision-number>]]` | Base or saved-revision links open the relevant local editor view. Normalize legacy `/#editor` via replace and keep editor work separate from learner progress. Direct draft edits require the existing local catalogue/API. |

Use current IDs for routing independently of display titles. A typed URL parser validates language, route shape, enums and segment lengths. Resolve entity membership after the relevant catalogue or course is ready. Canonicalize known aliases or defaults with `replaceState`. Unknown route shapes get a clear unavailable-page screen or server 404 as appropriate. For unknown IDs, removed revisions, invalid steps or unavailable offline content, explain what could be opened and offer a valid parent destination, a retry or the current lesson. An explicit valid URL takes priority over the last saved cursor. Reopening a previously visited step never writes a new navigation cursor by itself.

## History and state rules

| Action | Browser behavior | Learner state |
| --- | --- | --- |
| Open or change a destination, lesson, day, step or question | Push one unique visit. Deduplicate repeat clicks to the current destination. | Capture the old view context, stop active audio, open the target and focus its heading or player. |
| Normalize an alias, resolve a default resume or recover an obsolete step | Replace the affected entry. | Resolve the destination once after content loads and give useful status when recovery changes what is displayed. |
| Open the listening lesson chooser | Push an in-tab view entry at the same URL. | Back dismisses the chooser and restores play. Forward can reopen the chooser in the same tab. Selecting a lesson replaces the chooser entry with the new player destination. Search stays in memory. |
| Answer, check, reveal a transcript, play or pause, type a filter, toggle details | Update the view in place. | Keep temporary view state for the visit. For durable actions, preserve the existing explicit writes and retry semantics. |
| Use browser Back, Forward, or an equivalent in-app return | Read and validate the reached URL and applicable entry identity. | Restore view and focus after layout. Cancel in-flight audio and discard stale callbacks. Load persisted completions through existing reads. |
| Open a copied URL or reload | Resolve the current URL with entry metadata optional. | Restore the destination even with no visit snapshot. Restore durable progress from IndexedDB and start a clean temporary question or exercise when its snapshot is absent. |

Use one web history adapter at the app boundary and one typed destination resolver. Add a small versioned entry identity to existing `history.state` and preserve other keys. Keep bounded per-visit snapshots in memory with revision checks, and discard superseded forward snapshots on a new branch of history. Keep scroll and focused-item references in that context. After reload, initialize from the URL or recognized entry and render a valid initial view when snapshots are missing. Commit navigation and handle `popstate` through separate paths so a traversal creates zero entries. Preserve native navigation bindings through the same destination callbacks where applicable.

Use **Previous sentence** in listening as an in-app counterpart for learners who hide browser chrome. Reuse the matching previous visit when available. For a directly opened question, resolve the previous question in the current deck and disable the action at the start. Apply a new visit key when a question is reached again after looping through the deck. Stop or cancel pending speech and state updates on leaving, changing lesson, browsing and reopening. The player starts silent after restoration. From the library, **Back to practice** returns to the originating visit when it exists. Direct library links have a deterministic return to practice, with no dependency on an external previous page.

When a required save is busy or has a recoverable error, keep Retry/Dismiss available. On a traversal within the app's own history when the guard applies, return to the originating entry once by a verified index delta and suppress only that restoration event. Handle unknown and out-of-app entries through normal browser traversal. Give pending actions stable IDs and tie callbacks to their initiating visit, so retries remain idempotent and late callbacks cannot redirect another screen. Preserve mounted editor draft text during a same-tab detour and use browser unload protection for genuinely unsaved edits where appropriate. Keep typed input undo using the browser's normal shortcut. A saved editor preview route can select its revision. Creating a preview receipt and publishing still require their existing explicit controls. Navigating away from recording or live AI work ends the temporary session and releases media. Revisiting that screen shows a fresh start action.
