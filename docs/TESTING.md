# Verification

## Commands

```sh
npm run check
npm test
npm run test:e2e
npm run test:offline
npm run build:web
npm run check:staged
git diff --check
```

Install dependencies with `npm ci`. Before the first browser run, use `npx playwright install chromium`. PowerShell users can use `npm.cmd` / `npx.cmd`. Browser checks start Expo on localhost:8081 or reuse that server, plus an isolated in-memory API at 127.0.0.1:3002. Stop unrelated servers on those ports first. Editor tests proxy only the tested browser to this isolated API and never publish to the owner's on-disk database or call a paid provider.

## Existing checks

- `check`: repository structure, deliberately small TOML configuration subset, skill frontmatter, hook shape, local Markdown links, script syntax, Git whitespace, and TypeScript for application/shared/test code.
- `test:tooling`: 18 tests covering staged-secret scanning, ignored data, configuration parsing, installer behaviour, lifecycle hooks in temporary repositories, reproducible offline manifests and the guarded static preview server. These do not prove Codex runtime hook trust or loading.
- `test:app`: 94 tests covering content/answers, topic counts/search/IDs/actual sentence-button solvability, revision-scoped overview/per-entry progress, media coverage/target guards/unknown IDs, IndexedDB migration/idempotency/cache, backup merges/format1→2 compatibility, speech fallback, content requests, SQLite editor/security and manual recognition scheduling. Updated coverage verifies fuller examples, optional gender/notes, legacy presentation, published metadata/foundations grouping/filtering and immutable trusted seed refresh with owner-edit preservation/idempotence/rollback. Offline tests validate estimates, unsupported contexts and worker caching via a VM/fake CacheStorage: atomic completion, malformed manifests, response/hash/size/quota failures, retry, incomplete/evicted entries, old-copy retention, cache-only removal, Web Locks across generations and stalled-document deadline semantics. These fakes do not establish real browser quota/eviction behavior. Curriculum snapshot/CLI tests cover full immutable history/WAL, corruption including damaged indexes, schema/foreign objects/size limits, no-overwrite aliases/races, independent recovery, native timeout rejection, cleanup, actual child CLI commands and configured recovery startup on isolated ports. Review tests cover interval caps, supported/independent dates, early/same-day recall, edited-note revision scoping, timezone/DST and immutable IDs; v3 ratings persist and participate in backup rollback. Backup checks cover invalid/corrupt/oversized UTF-8 files and personal-note preservation.
- `test:e2e`: Chromium desktop/phone-sized learner regressions plus the isolated editor journey through draft save, preview isolation, explicit review/publication, later-draft separation, cache/reload and historical learning preservation. Narrow editor forms support keyboard entry and preserve unsaved text across learner navigation. Publication has one desktop writer; the duplicate mobile publication case is deliberately skipped against shared test content. Screenshots/traces stay in ignored `test-results/`.
- `build:web`: real Expo/Metro web export under ignored `apps/learner/dist`.
- `test:offline`: builds the current export first, then runs six Chromium desktop/320px journeys on an isolated port-8082 test server. Do not reuse the regular owner preview; stop it before this suite. Test-only in-memory response modes simulate interrupted/corrupt downloads, updated documents and stalled connections. Cold pages reload with browser networking disabled; removal checks all four learner stores and an unrelated cache. Test fixtures never open owner SQLite or browser profiles. The production static server has no test control endpoints.

The staged check inspects actual index bytes for protected paths and high-confidence credential patterns without printing values. It cannot detect every secret and does not run the full application suite. This preview has no CI deployment service.
