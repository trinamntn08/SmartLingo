# 0016 — Optional AI conversation boundary

Date: 2026-11-15. Status: accepted for local implementation.

AI practice is an optional learner action on the Practice page, separate from curriculum editing and ordinary lessons. Context uses the chosen lesson's topic, learner role and estimated level. The shared domain defines bounded, provider-independent request/reply contracts; the API coordinates temporary sessions and an injected provider adapter. A configurable OpenAI Responses adapter owns authentication, structured output and provider parsing. Permanent credentials never cross into learner assets, and no model or price is silently selected.

Only explicit Send or Transcribe recording invokes a provider request. Starting/checking availability, recording locally, navigating, replaying the existing device voice and saving an already displayed phrase incur no AI generation calls. Replies provide French, visible English translation, optional formative feedback and one optional suggested phrase. Output remains unreviewed practice assistance and cannot publish or change curriculum or establish proficiency.

Session history is held in process memory for at most thirty minutes and cleared on explicit stop/server close. The learner also discards conversation state on leaving practice or reload; only explicit notebook capture persists. Provider requests use store:false, which is not a promise about provider retention policies. Privacy text distinguishes external processing from local retention. No transcript, audio or credential logging is added.

Server limits reserve a daily attempt before making a request; failures can consume attempts because billing may already have occurred. Bounded session turns, one active provider request, request-ID replay/conflict handling and abortable timeouts prevent uncontrolled automatic retries. Limits and provider-reported token totals are in memory and reset when the local server restarts; this is a personal loopback safeguard, not durable billing enforcement. No automatic top-ups or background requests exist. Exact loopback Host/origin plus dedicated JSON/custom-header protection extend the editor's browser boundary; public or LAN hosting remains unsupported.

Device speech remains the explicit replay mechanism with a text fallback. Optional browser recording requests the microphone only on Record, caps local clips at thirty seconds/two MiB and stops tracks on stop/discard/navigation. Clips remain in memory. A separate explicit transcription upload returns editable text before a separate conversational Send; no recording automatically sends a turn. The API uses a route-specific bounded JSON/base64 body and validates encoding/decoded size/MIME, then an injected adapter uploads multipart audio to the configured transcription model. Request tombstones use content hashes rather than recordings, share request limits/single flight, cache only bounded text results and do not append audio to history. Clear temporary buffers after processing. This does not promise immediate erasure from managed memory or provider zero retention. Generated speech/cache and realtime duplex conversation remain later work. Tests inject providers and never require real credentials or paid calls.

Official wire references checked on 2026-11-15: [Responses text generation](https://developers.openai.com/api/docs/guides/text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [file transcription](https://developers.openai.com/api/docs/guides/speech-to-text), [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder), [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia). The current APIs are verified by mocked request/response checks; live French quality and model/account compatibility remain owner checks.
